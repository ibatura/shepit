# Shepit: notes for Claude

Shepit is a macOS menu-bar app: local dictation (Ukrainian and English) and meeting transcripts for Teams, Zoom and Google Meet. User docs are in `README.md`.

## Working with the author

- Reply in Ukrainian. Messages are often dictated, so they can contain spoken self-corrections («…через Meet. Ой, через Teams»): follow the corrected intent.
- Write code, comments, commits and docs in plain English.
- Work on a branch of its own; never commit to `main` directly. Commit each finished change there with a short message that says what changed and why. End commit messages with the `Co-Authored-By` line the session gives.
- When the branch is ready, ask the author whether to open a pull request on GitHub (the author calls it an MR); push the branch and open it only after they say yes, never on your own, with a description of what changed and how it was checked. A small change gets no pull request of its own: commit it and it goes into a later branch. The author merges it themselves in the GitHub web UI: never merge anything into `main` (not with `gh`, the API or locally) and don't offer to. Once it is merged, update local `main` with `git pull --ff-only`.
- Each branch raises the version in `app/Resources/Info.plist` (the number agreed with the author) and writes its notes in `docs/releases/<version>.md`. After the merge, `.github/workflows/release.yml` tags `v<version>` on `main` and makes the GitHub release with those notes; a version already released is skipped.
- Install the app with `scripts/install.sh` to try a change.

## Rules

- **Everything stays local.** No network except model downloads the user asked for. No cloud services, no sign-in.
- **Never default user data to iCloud** or another synced folder, even though the author's Obsidian vault is there. Every new output gets a path setting in `settings.json` with a local default under `~/.local/share/dictation/`. Exception: SQLite databases (`stats.sqlite`, `meetings.sqlite`, `dictations.sqlite`) share one setting, `databasesFolder` (default `~/.local/share/dictation`); a new database goes there and gets no setting of its own.
- **Call content is confidential work material.** When checking a real meeting note or transcript, report only counts and short fragments, never whole passages.
- The author's own `~/.config/dictation/settings.json` is not changed by code or tests.
- Security and privacy settings (Accessibility, Microphone, System Audio Recording) are changed by the user, not by scripts.
- macOS ties Accessibility to the signing certificate: never create a new "Shepit Local Signing" certificate when one exists (`scripts/signing.sh`).

## Code

- SwiftPM package in `app/`:
  - `ShepitCore`: pure logic with tests (settings, dictionary, meeting session and notes, meeting names, language choice).
  - `ShepitEngines`: whisper.cpp, WhisperKit, Parakeet, Apple Speech.
  - `Shepit`: the app (menu, hotkeys, overlay, audio, call tap, Accessibility scan of meeting apps in `MeetingApps.swift`).
- `make test` runs everything: Swift tests, installer and signing tests, accuracy tools. It must stay green (649 Swift tests on 2026-11-20).
- `scripts/`: build, sign, install, uninstall, model downloads (pinned SHA-256 in `scripts/models/`).
